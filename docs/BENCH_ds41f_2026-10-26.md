## 2. 性能（C=1 / 2）—— 协议：每格 4 次、**丢第 1 次预热**、取后 3 次中位

载荷 = `dsh_15k_v2.jsonl` 真实 agent 文本 ×3 条，`outlen=256`（B840 的"基准段"），满 C 连续灌入、自然结束。

| C | ①聚合输出吞吐（含预填） | ②聚合解码吞吐（仅解码段） | ⭐③b 步时中位（主判据） | TPOT 中位 | TTFT 中位 | 截断率 | deg 中位 | deg>0.30 占比 | 失败 |
|---|---|---|---|---|---|---|---|---|---|
| **1** | **40.60 tok/s** | **47.00 tok/s** | **81.5 ms/步** | 20.8 ms/token | 736 ms | **100%** | 0.03 | 33% | 0 |
| **2** | **51.00 tok/s** | **33.30 tok/s**（每请求；**×C ≈ 66.6**） | **113.7 ms/步** | 26.5 ms/token | 837 ms | **100%** | 0.02 | 33% | 0 |

逐次原始（②聚合解码 / ③b步时 / deg）：

```
c1r1(预热,丢弃) 40.6 tok/s / 82.1 ms / 0.03
c1r2            47.5 tok/s / 81.7 ms / 0.03
c1r3            43.8 tok/s / 81.5 ms / 0.02
c1r4            47.0 tok/s / 81.5 ms / 0.03     ← 中位 47.0 / 81.5
c2r1(预热,丢弃) 31.4 tok/s / 111.4 ms / 0.11
c2r2            31.8 tok/s / 112.6 ms / 0.02
c2r3            33.3 tok/s / 113.7 ms / 0.03
c2r4            34.4 tok/s / 120.7 ms / 0.02    ← 中位 33.3 / 113.7
```

**读法（重要）**：
* ⭐ **C=2 的收益只体现在"墙钟聚合"**：① 40.6 → **51.0 tok/s（+26%）**；
  而 ② 是按请求的（33.3），**×C ≈ 66.6 tok/s** 才是总解码能力（比 C=1 的 47.0 高 42%）。
* ⚠️ **步时随并发上升**：81.5 → **113.7 ms（+39%）** ⇒ C=2 时每步要同时算两条序列，
  单条变慢是预期的；**步时是本配置的主判据（不含 AL，不受投机接受率波动污染）**。
* ⚠️ **截断率 100%**：`outlen=256` 上限把输出全截断了 ⇒ ①②③c 都是"上限段"的口径，
  若要"自然结束"的数字，需要 `outlen≥1024` 重测（见 §6 待办）。
* ⚠️ **deg>0.30 占比 33%**：3 次里有 1 次出现退化（8-gram 重复率 >0.3），
  中位 deg 仍健康（0.03/0.02）⇒ 这是本仓已知的"复制循环"偶发（B415），**不是基准脚本的伪影**。
