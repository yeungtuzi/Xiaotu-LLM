# 驻留路线的主线定位（实现前必读）

> 本文回答一个问题：**我们到底在做哪条路线，哪条只是特例？**
> 状态：**方向性定稿（2026-10-21）**；实现开工前先读本文，再读 `docs/TUNING_GUIDE.md` 与 `docs/RUNBOOK.md`。
> 详细实验与推导在 `docs/EXPERIMENTS.md`（B1053/B1055/B1056）与内部计划文档。

---

## 1. 一句话

**主线 = ds41f 式的「GPU 承担专家、CPU 兜底」；qfn 的「48 层全部进 GPU」是特例，用来量上限，不是产品目标。**
「显存放得下所有层」**不是**本项目追求的能力。

---

## 2. 两条线

| | **主线：ds41f（专家常驻 / 热专家池）** | **特例：qfn（整层常驻 / 全 GPU）** |
|---|---|---|
| 权重位置 | 专家在主机内存；GPU 只持**热专家** | 整层（全部专家）搬上 GPU |
| CPU 的角色 | **兜底 + 参与计算**（CO-MOE） | 逐步退出，最终**零 CPU 专家** |
| GPU 的角色 | **专家缓存 + 计算** | 唯一计算设备 |
| 目标场景 | 生产（decode 优先） | **单流上限探针** |
| 是否是项目目标 | ✅ **是** | ❌ 不是（qfn 小到放得下，仅此而已） |

### 2.1 qfn 为什么是特例

* qfn 的模型足以**全部塞进 3 张卡**（NVFP4 下 GPU 侧约 77.7 GB，KV 走 fp8）⇒ 才有"全驻留"这个选项；
* 它的**专家池几乎没有收益**（实测 C=1 净负：命中省下的 CPU 计算，被每层 D2H→CPU→H2D 的握手与 GPU partial 内核吃掉）；
  而**整层常驻收益大**（C=4 +9.2%，C=1 持平）——因为整层常驻**整段去掉**了该层的握手，而不是"少算一部分"；
* ⇒ qfn 的正确路线是**层常驻**；把它当成"专家驻留"的论据会得出错误结论。

---

## 3. 为什么 qfn 的"池负收益"**不能**外推到 ds41f

收益公式（两种实现都适用）：

```
净收益 = 命中率 × (被替代的计算时间 − GPU 计算时间) − 传输/换入代价
```

* **qfn（CPU 引擎已经很快）**：被替代的是 CPU 专家的 GEMM，GPU 侧省得不多；
  且每层握手固定成本照付 ⇒ 命中不赚 ✗
* **ds41f（CPU 是慢的一侧）**：GPU 专家计算替代的是 **CPU**，
  而 **decode 阶段几乎没有现代 GPU 会比 CPU 慢** ⇒ 命中就是净赚 ✓
* 只要**传输能被预取/重叠**，这个结论对"大显存但算力偏弱"的异构卡同样成立 ✓

⇒ **"池在 qfn 上不赚"是"CPU 够快 + 握手固定成本"的结果，不是"池这个机制不行"。**

---

## 4. 主线的设计要点

1. **GPU = 专家持有者**：显存越大，能常驻的热专家越多；命中率随容量上升，收益近似线性。
2. **异构卡完全可用**：大显存、算力弱的卡，**适合放更多专家并承担 decode 的专家计算**；
   它的短板（算力）主要伤 prefill，所以 **prefill 交给快卡，decode 可以全卡参与**。
3. **decode 优先**：任何调度/换入策略先保证单流 decode 的步时不退化；
   高并发吞吐是第二目标。
4. **数据面先量后定**：GPU 之间取专家优先 **P2P**，不可用则 **host relay**；
   两者都要先测带宽与延迟，再决定预取深度。
5. **衡量指标（主线专用）**：
   * **每 GB 额外显存带来多少 decode tok/s**（而不是"能不能全放下"）；
   * 命中率 → tok/s 的**弹性**（hit +10% 对应多少 tok/s）；
   * 单流步时、`deg`、以及 prefill 是否退化。

---

## 5. qfn 特例该怎么用（不要浪费它的价值）

* **量上限**：回答"零 CPU 专家时单流能到多少"（NVFP4 + 3 卡，粗估 85–100 tok/s）；
* **验证工程件**：NVFP4/W4A16 的反量化与 Marlin 路径、**层常驻的引擎路径**、多卡异构调度——
  这些**可以复用到主线**；
* **不挤占主线窗口**：它是一次性上限实验，跑完收，不作为产品形态维护。

---

## 6. 非目标（写下来避免反复讨论）

* ⛔ "把 48 层全部放进 GPU"作为产品能力；
* ⛔ TP=3（每层切 3 份 + 每层 all-reduce）；
* ⛔ 为了"全驻留"而默认开 MTP/DSpark；
* ⛔ 用 qfn 的专家池结论去否定 ds41f 的热专家池；
* ⛔ 在传输未测量前就上跨卡专家共享。

---

## 7. 验收口径（主线）

| 项 | 判据 |
|---|---|
| decode 单流 | 不低于当前基线；开池后步时下降 |
| 显存效率 | 每 GB 额外显存 ≥ 约定的 tok/s 增益 |
| prefill | 不退化（允许 ≤2% 噪声） |
| 正确性 | 与关闭池逐题一致（greedy） |
| 稳定性 | 24h 无 OOM/泄漏 |
