# ds41f 显存效率验收摘要（2026-11-05）

> 单卡口径，2×A100-40GB（可用 39.49 GiB/卡），TP=2，MBT=8192，GPU_UTIL=0.9，
> 生产入口 `scripts/serve_ds41.sh`。全部数字为同机实测，未做外推。

## 1. 结论

| 项 | 改造前 | 改造后 | 变化 |
|---|---:|---:|---:|
| `nvidia-smi`（稳态） | 37,445 MiB | **26,315–28,269 MiB** | **−8.96 ~ −10.87 GiB/卡**（−9,176 ~ −11,130 MiB） |
| `reserved` | 35.89 GiB | **24.62–26.29 GiB** | −9.6 ~ −11.3 |
| `allocated`（活张量，未动） | 23.58 GiB | 22.6–23.6 GiB | ≈ 0 |
| **`frag`（缓存未用）** | **11.86 GiB** | **1.04–2.65 GiB** | **−9.2 ~ −10.8** |
| `free`（对驱动可用） | 2.48 GiB | **12.1–13.8 GiB** | **+9.6 ~ +11.3** |
| KV 池 | 4.58 GiB | 4.58 GiB | 0 |
| 专家池（15 槽/层） | 5.13 GiB | 5.13 GiB | 0 |
| MTP 常驻 | 0 | 0（实测否决） | 0 |

> ⚠️ **一句话限定**：上表是**短 prompt / 对话型负载**下的稳态。一旦发生一次 ≥3–4K token 的预填，
> 归掉的缓存会被重新申请且**不再归还**（实测 26,315 → 37,855 MiB 且不回落），
> 该实例此后接近改造前水位，直到重启。⇒ 本改动的真实价值是**稳态安全余量**
> （`free` 2.48 → 12–13.8 GiB，OOM 风险下降）与**消除"永远用不到的 11.86 GiB 缓存"**，
> 而不是"任何时候都省 10 GiB"。

## 2. 这 10.8 GiB 是什么

**形状预热的高水位**，不是稳态需要。对照实验（`WARMUP=0`，其余口径不变）：

| 指标 | 有预热 | 无预热 |
|---|---:|---:|
| `reserved` | 35.45 GiB | 24.62 GiB |
| `frag` | 11.86 GiB | 1.48 GiB |
| `nvidia-smi` | 37,445 MiB | 26,357 MiB |
| `allocated` | 23.58 GiB | 23.14 GiB |

预热要为 `compile_ranges=32,256,8192` 覆盖 8192-token 桶，峰值因此抬高；预热结束后
这部分变成 allocator 缓存、长期攥着。

## 3. 做法：预热收尾即归还

- 触发源：**预热日志出现"完成:"**（每次启动必然发生且只一次）；布防时记 EOF，
  只匹配**新增**内容（`_warmup.log` 是追加型，否则第 2 次启动会命中旧收尾行）；
- 安全门：`frag ≥ 3 GiB` 才动手；`synchronize` 后、`empty_cache()` **前**再确认最近
  5 s 无活动，否则放弃本轮（实测确实会放弃——第 3 次启动放弃了 6 次才等到安静窗口）；
- 只做一次；受 `XIAOTU_IDLE_EMPTY_CACHE=1` 控制，**`IDLE_EC` 默认已为 1**（要关用 `IDLE_EC=0`）。

实测：`预热收尾 ⇒ cuda:X 归还 10.40~10.73 GiB（reserved 35.0→24.6）`。

## 4. 被否决的路线（都有数据）

| 路线 | 结论 |
|---|---|
| MTP/dspark 专家常驻显存 | **否决**：三臂端到端 34.41 / 34.19 / 33.80 tok/s（差 <0.5%，噪声内）；代价 +3.36 GiB 且挤掉 KV 1.75 GiB。dspark 本体实测 **1.5 ms/draft-token（≈650 tok/s，eager）**，只占一步约 7% |
| 专家槽 15→24 | **负收益**：30.81 tok/s（−10%），KV 4.58→3.25 伤前缀缓存 + 410 次换入争带宽 |
| 专家槽 15→32 | **启动失败**（确定性）：`1.32 GiB KV cache is needed, which is larger than available` |
| 自适应热专家（15 槽） | 无变化（34.01 tok/s）；且热度表仅 17 条/层，槽数上限被表卡死 |
| MBT 8192→16384 | **装不下**：激活预算 ≈10.8 GiB @8192，每 1K token ≈1.3 GiB；16K 需 +10.8 GiB > 单卡余量。8K–15K 之间任何值对 15K prompt 仍是 2 个 chunk，收益只剩每 chunk 固定开销 |
| 提高 KV / 并发 | 无收益：KV 池从未被抢占过一次 |

## 5. 与 XTier 的差异（硬件代际，不是实现差距）

| | XTier 72 GB | 本项目 2×A100 40 GB |
|---|---|---|
| 专家槽 | 50 槽/层（≈17.5 GiB） | 15 槽/层（5.13 GiB） |
| decode | 141.8 tok/s | 34.4 tok/s |
| 专家算力 | SM120 原生 FP4/FP8 张量核 | SM80 无 FP4/FP8 单元，专家走 CPU AVX-512 |
| 数据位置 | 专家全在内存 + NVMe 三级 | 专家全在内存（47 GiB），无盘 |

XTier 把专家搬上卡是"从慢 CPU 搬到极快张量核"；本项目的 CPU 引擎（871 µs/层）
在 A100 上已具竞争力，搬到 GPU（旧 Triton 路径 1272 µs/层）反而更慢。

| TTFT（**含前缀缓存命中**，3 次中位） | 400 tok **602 ms**、1600 tok **568 ms**（与归还前一致） |

| `AssertionError` | **0** |
| 归还后真实请求 | `chat=200` |
| 长稳 | **5 次启动全部真实归还**（10.40/10.40/10.73/10.40/10.40 GiB）；背靠背时序专项通过；≥2 h 带流量长稳进行中 |

## 7. 复现

```bash
# 生产（默认就开启归还；要关掉用 IDLE_EC=0）
bash scripts/serve_ds41.sh restart PIN_SLOTS=15

# 观察
grep -E "预热收尾 ⇒|放弃本轮" ~/run/ds41_prod.log | tail
nvidia-smi --query-gpu=memory.used --format=csv,noheader
```

⚠️ 归还只在**启动时预热收尾**那一次发生；若服务启动后一直有流量，归还不会在负载中执行
（这是设计选择：宁可放弃，也不在有人使用时归还）。因此收益体现在**稳态**（26–28 GiB），
不改变**峰值**（大预填时仍会涨回约 37.8 GiB，因为分配器需要时会向驱动重新申请）。

## 10. 边界与已知限制

1. **不改变峰值**：归还的是 allocator 缓存，大预填时会重新向驱动申请（实测可回到约 37.8 GiB）。
2. **只在启动时那一次**：服务起来后一直有流量时不会归还（设计选择：宁可放弃，也不在有人使用时归还）。
3. **`WARMUP=0` 不归还**：没有预热高水位，且空闲线程已被让位。
4. **`IDLE_EC_SECONDS` 在本入口不生效**：入口总是设 `XIAOTU_RELEASE_AFTER_LOG`，该参数只在"未设触发器的兜底臂"有效。
5. ⛔ **归还是 one-shot**：一次大预填（≥3–4K token）会把缓存重新要回来且**不再归还**，
   该实例此后回落到改造前的 ~37.8 GiB，直到重启。⇒ 收益对**短 prompt/对话型**负载稳定，
   对**含长 prompt** 的负载只在长预填发生前有效。
5. 长稳（≥2 h 带流量）仍在进行，结果以 `docs/VRAM_LEDGER_ds41f_2026-11-05.md` 的判据表为准。

> ⛔ **2026-11-05 更正（实测收口，见账本 §二十六）**：本文早前把"GPU 常驻无收益"与
> "A100 无 FP4 单元所以 GPU 更慢"当作结论，这两条**均无实验基础**：
> ① 线上 `.so` 里 `moe4_smallm` 符号数为 0（`BUILD_MOE4` 默认关），该臂内核从未执行；
> ② 其中一臂我还把 `PIN_CUDA_MOE=1` 当环境变量传（它是位置参数），实际仍是 0。
> **同形状实测（H=5120 I=2304 E=384 K=6）**：CPU 1.14 ms/层 vs GPU 内核 4.51 ms/层
> （BS=6），但 GPU 只跑到 **0.07–0.14 TB/s**（峰值 1.55）⇒ 带宽下限约 **0.41 ms/层**，
> **GPU 本可比 CPU 快约 2.8×，当前实现离下限差 11 倍**。
> ⇒ 正确表述："当前内核实现有 11× 带宽利用差距"，**不是**"GPU 算不过 CPU"。
